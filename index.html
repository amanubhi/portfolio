The American Affordability Index

01

Python, pandas, DuckDB SQL, Streamlit, Plotly

Did renter income keep pace with selected essentials?

74.4% of the modeled 2015–2024 annual cost increase comes from rent.

Finding
Renter median income rose 51.8%; the illustrative rent, grocery, and gasoline budget rose 40.6%. The modeled affordability index reached 108.0 (2015 = 100).
Decision supported
Prioritize rent in budget sensitivity checks, then replace the model’s weights with the household’s own costs before acting.
Boundary
This is an aggregate, selected-cost model. It does not establish that every renter became better off or measure a complete household budget.
Dashboard ↗Case study ↗SQL queries ↗Validation tests ↗
How the analysis earns trust

Sources and implementation

Frozen Census ACS, BLS CPI, and EIA data pass through pandas validation, Parquet tables, and DuckDB SQL. The repository contains the Streamlit app; the public dashboard is a browser-only companion.

A consequential modeling choice

National rent CPI and state gross-rent measures stay separate: they have different definitions. National prices are not relabeled as state prices. Standard ACS 2020 is absent rather than filled with invented observations.

An interpretation rejected

The data did not support a blanket “everyone is worse off” story. Price-level correlation also did not establish that gasoline changes cause grocery changes. Both limits are documented.

Sensitivity, not certainty

Four tested budget weights produced indexes from 106.2 to 111.1. This checks a limited set of assumptions; it does not establish the result for all households. Input margins of error are retained, but derived rank confidence intervals are not claimed.

Personal portfolio analysis using public sources; no client deployment or realized business impact is claimed.

Does a Recommendation Nudge Change Engagement?

02

Python, pandas, SciPy, statsmodels, Matplotlib

Does the textbook sample-size formula actually work for engagement metrics?

3.2x — the real sample size needed once the formula’s equal-variance assumption failed on this metric.

Finding
A closed-form Cohen’s-d formula said 1,097 users per group; simulating the real data-generating process showed 3,496 were needed, consistently 3.19x–3.30x higher across four tested lift sizes.
Decision supported
Size experiments on skewed count metrics (sessions, purchases, errors) by simulation, not a generic power calculator — then validate the test’s own false-positive and power behavior before trusting any single result.
Boundary
A simulated experiment on real engagement variance with a disclosed, injected treatment effect. It demonstrates the experimentation workflow, not a measured result from any real product.
Repo ↗Executive summary ↗Validation ↗
How the analysis earns trust

Sources and implementation

Real per-user weekly engagement-rate heterogeneity comes from 610 MovieLens users’ rating activity; the treatment effect is a disclosed, injected assumption layered on top via a Poisson-mixture model.

A consequential modeling choice

statsmodels’ closed-form sample-size formula assumes equal variance in both arms. This metric’s variance scales with its mean, so the naive formula understated the required sample size by 3.19x–3.30x across every lift size tested — replaced with a simulation-based search instead.

An interpretation rejected

An early run at the naive (wrong) sample size produced a clean, significant result (p=0.004). It was rejected once A/A and power validation showed that pipeline was running at 31% power, not the intended 80%. A significant p-value from an unvalidated pipeline is not evidence.

Sensitivity, not certainty

2,000 A/A replications gave a 5.1% false-positive rate (target 5%); 1,000 power replications gave 78.8% empirical power (target 80%). Both fall inside their 95% confidence intervals.

Personal portfolio analysis using public MovieLens data with a disclosed synthetic treatment effect; no real product result is claimed.

Excel Salary Dashboard

03

Excel, dynamic arrays, XLOOKUP

How can a job seeker benchmark pay without hiding gaps?

67% of 32,672 postings disclose salary. Coverage belongs beside the pay figure.

Approach
Built dropdown-driven charts and KPIs with structured references, FILTER, UNIQUE, XLOOKUP, and MEDIAN(IF(...)).
Decision supported
Compare disclosed salaries for a specific title, country, and employment type rather than treating a global median as a personal pay expectation.
Boundary
Missing salaries can create selection bias. Empty salary selections currently return #NUM!; this known limitation is documented.
Excel workbook ↗Formula walkthrough ↗
Ownership, course credit & AI assistance

Built by hand through Luke Barousse’s Data Analyst course. The course supplied the dataset and dashboard concept. The repository credits AI assistance for packaging, README structure, formula verification, dataset-wide summary calculations, and publishing.

The formula-driven workbook uses no PivotTables or VBA. Salary and job-count results depend on the selected filters; they are not universal market estimates.
